# Security Policy

## Reporting a vulnerability

Please **do not open a public issue** for a security problem.

- Use GitHub's private vulnerability reporting: **Security → Report a vulnerability** on this repository.
- If that is not available to you, open a regular issue that only says you have a security report and asks for a
  private channel — without any technical detail — and the maintainer will contact you.

Include what you found, how to reproduce it, and the impact you expect. You will get an acknowledgement within a few
days. Please give us a reasonable time to fix the issue before disclosing it.

This is a hackathon project running on **Solana devnet only**; mainnet is refused by design. Reports about the signer,
the validator, tenant isolation or receipt verification are the most valuable.

## Secrets model

- **No secret lives in this repository.** Configuration files ship without default values for credentials
  (the shared `application.yml` has no default for any of them, and a test enforces it); `.env.template` documents the variables
  with empty values.
- **The demo environment is generated locally.** `scripts/demo/wallet-devnet.sh` creates the devnet keypairs under
  `~/.cryptobot-demo` (mode `0700`) and writes `.env.demo`, which is gitignored. Nothing generated by the demo is ever
  committed.
- **The signer is isolated.** The service never holds a private key: a separate `signer` process, gated by an independent
  `validator`, signs only what its policy allows (memos and transfers to allow-listed wallets, capped per transaction).
- **Test fixtures are test-only.** Keys that appear under `src/test` (for example the Ed25519 key of the receipt golden
  vectors) are generated for the test suite, documented as such in the file, and used by no environment.

## Repository history audit (2026-09-30)

Before publishing, the full Git history was scanned with **gitleaks 8.30.1** (`gitleaks git`, all commits).

- **Result:** 19 findings in 11 commits.
- **Classification:**
  - test API keys and similar literals inside `*Test.java` files (fake values used as test inputs);
  - the Ed25519 key of the receipt golden vectors (`src/test/resources/receipt/vectors-v1.json`), a test vector that
    was **replaced in the current tree** by a newly generated, test-only key;
  - Spring Boot generated passwords printed in Surefire reports that were committed by mistake and later deleted
    (per-run random values of a test context).
- **Verification:** every finding was compared **by fingerprint** (never by printing the value) against the credentials
  in use by every runtime — the local demo, staging, UAT and production. **None of them is in use anywhere.**
  A development `JWT_SECRET` that appears in older history was audited the same way and is not in use either.
- **Decision:** the history is **not rewritten**. Rewriting would break every existing clone and reference while
  protecting nothing, because no finding is a live credential. The current tree scans clean (reviewed exceptions are
  listed, with their reason, in `.gitleaksignore`).

No secret values are reproduced in this document.
